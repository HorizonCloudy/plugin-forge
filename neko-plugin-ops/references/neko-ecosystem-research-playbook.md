## 三、市场全量抓取（SPA 逆向技巧）

市场页 `https://market.project-neko.cn/#/plugins` 是 SPA：
- `WebFetch` 只拿到 `<title>`（壳）。
- 主 JS 包里**没有任何 `/api` 字面量**——路径被变量拼接/混淆。
- **直接打分页 API 最快最准**：

```bash
# 翻页直到返回的 has_next=false（实测 7 页，20/页）
curl -s "https://market.project-neko.cn/api/v1/plugins?page=1&page_size=20"
# 返回结构：{ "total": 135, "items": [...], "has_next": true, "page": 1, "page_size": 20 }
```

每条 `item` 关键字段：`name`、`zone_slug`（分区）、`tags`、`categories`、`download_count`、`short_description`、`is_featured`、`status`。

Python 合并示例：

```python
import json, urllib.request
base = "https://market.project-neko.cn/api/v1/plugins"
items = []
for p in range(1, 8):
    with urllib.request.urlopen(f"{base}?page={p}&page_size=20", timeout=30) as r:
        d = json.load(r)
    items += d["items"]
    if not d.get("has_next"):
        break
print("TOTAL:", len(items))
```

> 逆向收益递减法则：若 API 路径也混淆，优先试 `/api/v1/...`、`/api/.../list` 等常见变体；成本过高就改用权威源做推断并标 [INFERENCE]，不要用 Playwright 硬抠 vendor 包（除非需要逐条 UI 文本）。

## 四、精确类目统计方法

拿到全量 `items` 后：

1. **分区分布**：`Counter(i["zone_slug"] for i in items)`。
2. **Tag 分布**：展开每个插件的 `tags` 计数。
3. **下载榜**：按 `download_count` 降序，看头部 plugin 品类（往往暴露"生态真正被消费的是什么"）。
4. **关键词扫描**：用 情感/关系/桌宠 关键词（情感/情绪/心情/日记/陪伴/抚摸/投喂/表情/动作…）对 `name+描述+tags` 做命中扫描，量化"真实情感/桌宠类"占比。
5. **交叉验证**：把 companion 区单独拆开看其 `tags`——避免"陪伴区数量多"误导结论。

> 关键陷阱：**分区名会骗人**。companion 区 34 个里 31 个带"游戏"tag（91%），所以"陪伴区不小"≠"情感/桌宠不少"。必须用 tag/关键词二次切片。

## 五、三轴缺口分析框架

以产品定位（陪聊/陪伴/桌宠）为基准，逐轴比对"现状 vs 应有"：

| 轴 | 问法 | 看什么 |
|------|------|------|
| **陪聊** | 猫娘会不会"主动、有温度地聊"？ | 情绪觉察、每日仪式、关系里程碑、冲突安抚 |
| **陪伴** | 能不能"一起做点非游戏的事"？ | 一起看番/读书/学习/做饭/冥想、记忆创造性利用 |
| **桌宠** | 桌面上的"活物感"够不够？ | 抚摸/投喂/清洁、待机动画、点击/拖拽反应、随心情换动作 |

每层标注证据等级。若某层"现状≈0"，先查是不是**平台级阻塞点**（见下），而非"没人做"。

## 六、平台级阻塞点核对清单（坐实 [FACT]）

做桌宠/情感类插件前，必须核对官方 SDK 是否给入口。2026-11-04 实测结论（已从 `project-neko.online` 文档坐实）：

| 缺失钩子 | 核对方法 | 结论 |
|---------|---------|------|
| **Avatar 表现控制** | 查 `plugin.sdk.plugin` 完整导入面有无触发 Live2D/VRM 表情/姿势/动作的 API | **缺失** [FACT] |
| **情绪/好感状态读写** | 查 Tool Calling 文档是否提供修改猫娘情绪/强制行为的 API；`bus` 是否含 companion 自身情绪 store | **缺失** [FACT]（文档明示"未提供直接修改猫娘情绪的专用 API"） |
| **桌面交互事件** | 查有无内建 click/drag/feed/pet 事件源（`@message` 只接 chat） | **缺失** [FACT] |

> 意外可用能力：`get_os_activity_snapshot()`（OS 活动感知）+ `bus.frames`（用户屏幕帧）——可做"感知型陪伴"，利好"一起看番"类插件。

**用法**：把"平台阻塞点"作为缺口报告的最高优先级，并作为"向官方提 SDK 扩展需求"的弹药。上层插件再热闹也补不上被平台卡死的层。

## 七、证据分级（团队宪法要求）

每张缺口报告必须标注：
- `[FACT]`：可验证（来自上方链接 / 实时 API 返回）。
- `[INFERENCE]`：基于假设推导（如"游戏偏重、情感偏轻"来自可见清单 + 能力统计交叉）。
- `[GUESS]`：证据不足。
- `[VALUE JUDGMENT]`：涉及偏好/伦理。

不确定就直说不确定，不糊弄。

## 八、实测快照（2026-11-04）

- **总量**：135 个在架插件 / 10,176 次下载（2026-11-04 抓取；对比 2026-10-26 的 127 个，仍在增长）。
- **2026-11-06 复核**：在架总数 **仍为 135（未变）**；总下载 **10,407**（云调核验时点）→ **10,413**（主理人同日二次实测，全 7 页求和），属活体增长，一律以实时 API 为准。下方分区与情感占比仍为 11-04 快照口径，未重算，引用时须标日期。
- **分区**：tool 53 · **companion 34** · function 24 · game 12 · entertainment 12。
- **companion 区真相**：34 个里 **31 个带"游戏"tag（91%）**——所谓"陪伴区"实为"游戏代打区"。
- **真实情感/关系类插件**：约 8–10 个（≈7%），如 她的一天 / 永远的陪伴 / 精力状态 / 猫娘日记 / Call Mom / 一言 / 猫爪渔力·副驾 / Recall陪伴式记忆 / 自拍。
- **桌宠本体层（抚摸/投喂/avatar 互动机制）**：≈ 0——根因是 SDK 无钩子（见第六节）。
- **下载榜头部**：战雷 Copilot 2336 / 酒狐 1280 / 尖塔 1224 / PVZ 792（2026-11-04；清一色游戏代打）。
- **2026-11-06 复核**：战雷 Copilot 2344 / 酒狐 1288 / 尖塔 1228 / PVZ 802→803（云调核验时点为 802，主理人同日二次实测已 803；榜序未变，活体增长）。

**核心结论**：生态"工具 + 游戏代打 强、陪伴感薄"；最深的桌宠层不是没人想做，而是**被平台 SDK 卡死**。
