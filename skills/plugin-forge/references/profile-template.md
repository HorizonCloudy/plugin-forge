# 目标平台 Profile 模板

> profile = 目标平台的**契约快照**。团队核心平台无关；接入新平台只写 profile。
> 复制本模板为 `profile-<平台>.md`，逐节填写。所有能力面结论必须 `[FACT]`（附文档/源码出处）
> 或 `[未核验]`，**不许 `[INFERENCE]` 硬说"应该支持"**（宪法第 11 条）。

# profile：<平台名>

> 核验日期：YYYY-MM-DD；核验人 / 方式：<谁、怎么核的>

## 1. 身份与安装形态
- 平台是什么、插件以什么形态安装（目录 / zip / 商店上架 / 本地加载）
- 插件运行模型（独立进程 / 宿主内 / 沙箱 / Web Worker…）

## 2. Manifest 契约
- 文件名与必填字段（逐字段：类型、约束、示例）
- id 命名规则与"发布后可否更改"
- 版本与 SDK 兼容区间写法

## 3. 入口与生命周期
- 宿主加载入口怎么声明（`模块:类名` 之类）
- 运行时入口 / 对话工具入口 / 事件入口——各是什么、怎么声明、**互不可混用**
- 启动 / 关闭 / 定时 / 消息钩子的签名与同步性要求（如强制 async）

## 4. 能力面（审议核心）
- **明确支持**：逐项列出（消息、存储、网络、UI、模型调用…），每项附文档/源码出处
- **明确不支持**：逐项列出（这是封驳依据，越具体越省一轮）
- **怎么降级**：不支持的能力有什么官方替代或降级路径

## 5. 错误约定
- 成功 / 失败的统一返回结构（如 `Ok/Err`）
- 可不可以 `raise`、哪些位置禁止 raise
- 日志与错误脱敏要求

## 6. 硬性限制速查
- payload 上限、超时、频率、目录权限（代码目录只读？数据写哪？）
- 安全约束（回调只走回环？密钥能放哪？）

## 7. 沙箱与验证命令
- 隔离运行时怎么搭（命令序列、隔离哪些目录/端口/环境变量）
- **真实存在的**健康 / 状态路由（逐条附源码出处），明确列出**不存在或非 GET** 的易错路由
- "加载成功"的判定标准

## 8. 生态与市场
- 市场/商店列表入口、分页 API 形态、历史样本分母口径
- 官方源：仓库 / 文档 / 示例插件清单
