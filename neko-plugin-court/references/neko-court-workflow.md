# 朝议工作流（NEKO 插件版）

## Workflow A：完整朝议（做一个插件 / 加一个功能）

| 阶段 | 执行者 | 产出 |
|---|---|---|
| 1. 接旨分拣 | 太子 | 任务 ID + 一句需求概括；**先确认是"修"还是"改"** |
| 2. 起草方案 | 中书省 | ≤500 字：定位 / 入口 / 装饰器 / 数据 / 依赖 / 验收 / 风险 |
| 3. 契约审议 | 门下省 | 准奏 / 封驳（重点核 SDK 限制） |
| 4. 派发 | 尚书省 | 按部拆分，无依赖的并行 |
| 5. 实现 | 工部（+ 礼部文档 / 刑部审查并行） | 完整代码 + `plugin.toml` |
| 6. 安装验证 | 兵部 | 确认能加载、无 entry-404 |
| 7. 验收回奏 | 尚书省 → 太子 | 三段式，含"需你手动"项 |

**不可跳步**：没有门下省准奏，不许动手写代码。

## Workflow B：快速问答

「entry 是什么」「这插件怎么装」「为什么报 403」——太子直接答，不建任务。

## Workflow C：封驳重拟

门下省封驳 → 中书省只改被驳部分 → 重新送审 → 连续 2 次升级用户裁决。

**插件场景的高频封驳原因**（提前避开能省一轮）：
1. 方案要 SDK 没有的 API（表情/动作/情绪/桌面事件）
2. 用 `@llm_tool` 当入口
3. 定时回调里 `raise`
4. 外部文本拼进系统提示词
5. 没写失败降级

## Workflow D：单部直调（排障专用）

「插件启动失败了」→ 太子直接派**兵部**，跳过中书/门下，但回奏必须注明「单部直调」。

- 适用于：entry-404 / 启动 failed / model-403 这类**已明确是运行时问题**的场景
- 不适用于：要改功能（那是 A）、要动架构（A）

## 验收清单（尚书省按此收）

- [ ] `plugin.toml` 语法正确，入口名与代码一致
- [ ] 入口用 `@plugin_entry` + `llm_result_fields`
- [ ] `logic.py` 不 import SDK（可离线测）
- [ ] 定时回调有 try/except
- [ ] 网络有超时与降级
- [ ] 外部输入不进 `eval`，URL 有 `quote`
- [ ] 数据落盘有清理策略
- [ ] 实际加载过一次，不是"文件写完就算"

## 失败处理

| 情况 | 处理 |
|---|---|
| 加载失败 | 兵部看日志定位；区分代码问题 / 配置问题 |
| 契约不符 | 退回中书省改方案，不硬改代码将就 |
| SDK 做不到 | 钦天监确认 → 降级方案 → 用户裁决 |
| 范围蔓延 | 只报告不顺手改；新增需求另开朝议 |
