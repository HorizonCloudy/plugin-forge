为什么插件需要朝议

做 N.E.K.O 插件最容易翻车的地方不是写不出代码，而是方案在 SDK 上根本做不到：想让猫娘做表情回应你、想让她因为你摸她而害羞、想让她主动生气——这些 SDK 都没有 API。大多数时候，这些是写了两小时代码才发现的。

SDK 明确不支持的（门下省会因此封驳）

想要的能力现状
控制 Avatar 表情 / 姿势 / 动作无 API
直接修改猫娘情绪 / 强制行为无专用 API
桌面交互事件（点击 / 拖拽 / 投喂 / 抚摸）无内建事件

可用的是 OsActivitySnapshot / get_os_activity_snapshot() / bus.frames —— 支撑感知型陪伴（知道你在干什么，然后说点什么），不是控制型交互。

四条工作流

流程适用
A · 完整朝议做一个插件 / 加一个功能，七步不可跳步
B · 快速问答「这插件怎么装」「为什么报 403」——直接答
C · 封驳重拟方案被驳回 → 只改被驳部分 → 重新送审
D · 单部直调排障专用：启动失败直接派兵部
